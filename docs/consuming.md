# Installing and using the packages

Choose a version whose main CI candidate and relevant registry job both passed.
The release manifest supplies the exact version. An Actions artifact named candidate
is a tested archive; it becomes a registry package only after upload. Versions such
as `1.0.0-ci.12.1` below are illustrative, not assertions that those releases exist.
The [accepted WP03.00 publication](releasing.md#wp0300-accepted-publication)
records the complete published set and its channel identities at that time.

C# NuGet is the only first-party SDK channel for business clients (CON.40, P2-021
Decision 4). The TypeScript and Kotlin packages are
[retired from new publication](#retired-typescript-and-kotlin-packages).

## C#

A repository using central package management adds these entries to
`Directory.Packages.props`:

```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="ArcForges.Contracts.PublicApi" Version="1.0.0-ci.12.1" />
    <PackageVersion Include="Grpc.Net.Client" Version="2.84.0" />
  </ItemGroup>
</Project>
```

The application's project references them without inline versions:

```xml
<ItemGroup>
  <PackageReference Include="ArcForges.Contracts.PublicApi" />
  <PackageReference Include="Grpc.Net.Client" />
</ItemGroup>
```

Enable `RestorePackagesWithLockFile`, commit `packages.lock.json`, and use
`dotnet restore --locked-mode` in CI. nuget.org is the public source; no publishing
credentials are required for a consumer.

```csharp
using ArcForges.Contracts.Hello.V1;
using Grpc.Net.Client;

using var channel = GrpcChannel.ForAddress("http://localhost:50051");
var client = new HelloService.HelloServiceClient(channel);
var reply = await client.SayHelloAsync(
    new SayHelloRequest { Name = "World" },
    deadline: DateTime.UtcNow.AddSeconds(5));
Console.WriteLine(reply.Message);
```

The local example server can be run from the Contracts checkout after restore:

```text
dotnet run --project tests/public/HelloHost -- --grpc-port 50051 --web-port 50052
```

That server is a loopback test fixture. A real application supplies its own
service implementation, TLS endpoint and authentication. Public business clients,
including browser (Blazor WebAssembly) and Android (.NET MAUI) applications, use
binary gRPC-Web for the public Worker ingress; the application composes that
transport, its credentials and its lifecycle. The packages create no global channel.

### Operation metadata

`ArcForges.Contracts.PublicApi` carries the public operation rows (authorization,
risk and binding per operation) as `operations/operation-metadata.v1.json` at the
package root. Pin the exact version in `Directory.Packages.props` and
`packages.lock.json`, and read the file from that restored package; never read it
from a Contracts checkout or source tree. Setting
`GeneratePathProperty="true"` on the package reference gives MSBuild the restored
package folder:

```xml
<ItemGroup>
  <PackageReference Include="ArcForges.Contracts.PublicApi" GeneratePathProperty="true" />
</ItemGroup>
<PropertyGroup>
  <ArcForgesOperationMetadata>$(PkgArcForges_Contracts_PublicApi)/operations/operation-metadata.v1.json</ArcForgesOperationMetadata>
</PropertyGroup>
```

The file is an `operation-metadata.v1` document ordered by `operationId`, and every
build of a given version carries the same bytes. Updating the pinned version is the
only way its rows change; review the row differences with the version update.

## Local operation dispatch (internal C#)

`ArcForges.Contracts.LocalRpc.Dispatch` (CON.43) is an internal-access NuGet package
for the local product host. Public business clients must not reference it. It
depends on exactly four Contracts packages: `ArcForges.Contracts.PublicApi`,
`ArcForges.Contracts.LocalRpc.Platform`, `ArcForges.Contracts.LocalRpc.Scope` and
`ArcForges.Contracts.LocalRpc.Chat`. It is the only Contracts assembly where the
structured value (`CapabilityArguments`, `CapabilityResult`, `StructuredValue`) meets
the typed Scope and Chat requests. It has no listener, service registration or product
implementation.

All of its code is generated by `eng/local_operations.py` through
`python eng/contracts.py generate`. For each tool-eligible `IScopeOperations` and
`IChatOperations` method (19 operations; `IChatOperations.SubmitApproval` and every
infrastructure-port method are excluded) it holds:

- the request and result schemas (`RequestSchema`, `ResultSchema`, dialect
  `arcforges.local-operation-schema.v1`);
- a non-reflective decoder, `TryDecode(arguments, meta, context, ...)`. It refuses an
  unknown field, a missing required field or an out-of-bounds value with a typed
  `LocalOperationFault` before any owner code runs;
- a result encoder, `TryEncodeResult(value, ...)`, which validates the owner result
  and the structured result before delivery;
- the symmetric `TryDecodeResult` and `TryEncodeArguments`.

`LocalToolAllowlist` is the closed allowlist. `TryResolve(capabilityKey, out operation)`
matches only exact capability keys of operations that the operation-scope gate admits
as tool rows. At CON.43 that is exactly one key, `IScopeOperations.CreateAnnotation`.
The other 18 decoders exist, but no key resolves to them. The
[package README](../src/internal/dotnet/ArcForges.Contracts.LocalRpc.Dispatch/README.md)
gives the value mapping and the fault kinds.

A consumer binds these functions through its own thin adapter. The adapter:

1. resolves the capability key with `LocalToolAllowlist.TryResolve`. If the key does
   not resolve, the adapter refuses the call with
   `new LocalOperationFault(LocalOperationFaultKind.UnknownCapability, "")`;
2. calls the operation's `TryDecode` with the caller's `RequestMeta` and
   `LocalCallContext`, and calls its own operation implementation only when the
   decoder returns the typed request;
3. returns the result of `TryEncodeResult`. A fault from any step becomes
   `fault.ToArcError(correlationId)`: `validation.invalid_request`, category
   validation, no retry, did not happen.

The adapter must not map fields itself, relax a refusal or keep a second allowlist.
The adapter cannot be skipped. The ArcForges.Capabilities decoder and encoder
delegates return `ArcForges.Foundation.Errors.Outcome`, a DesktopPlatform type that
Contracts does not reference, so they cannot bind to the emitted functions by method
group. The product host's adapter does the wrapping. APP.03 does this for the
`arcscope.annotation.create` capability, which resolves to
`IScopeOperations.CreateAnnotation`.

All packages from one candidate share one version. Pin the Dispatch package and
each of its four Contracts dependencies to that same exact version in
`Directory.Packages.props`, and restore with the committed lock file as above.
Running the decoder in the Native AOT product host is APP.03's acceptance. It is
blocked on APP.03 and not proven in Contracts.

## Flagship contracts (C#)

AF-CON-01 adopts the ArcForges-Design specification protos unchanged, recorded with their
digests in [`eng/flagship-contracts.json`](../eng/flagship-contracts.json):

| Package                     | Access   | Contents                                                                          |
| --------------------------- | -------- | --------------------------------------------------------------------------------- |
| `ArcForges.Contracts.Node`  | public   | `arcforges.node.v1`: 20 files, 19 services (the local node API)                   |
| `ArcForges.Contracts.Fleet` | public   | `arcforges.fleet.v1`: 3 services (the cloud fleet API); depends on Node           |
| `ArcForges.Contracts.Peer`  | internal | `arcforges.peer.v1`: 6 services (node to node and host to guest); depends on Node |
| `ArcForges.Contracts.Relay` | internal | `arcforges.relay.v1`: relay frames, messages only; depends on Node and Fleet      |

The reused packages gain one additive file each, with their existing namespaces:
`ArcForges.Contracts.PublicApi` carries `SupportAccessService` (`support_access.proto`)
and the internal `ArcForges.Contracts.CloudInternal` carries `OperatorReadService`
(`operator_read.proto`). Their other services are unchanged.

Flagship code imports `ArcForges.Contracts.Node.V1` (and Fleet, Peer and Relay), never
the retained `publicapi.v1` task, workspace, policy or approval services, whose simple
names repeat with different fully qualified names (design reuse map, conflict C-04).
Each RPC carries its design annotation block (`auth`, `idempotency`, `deadline`,
`stream`, `errors`, `locality`, optional `state`); error codes are listed in
[`fixtures/public/af-con-01-error-catalogue.json`](../fixtures/public/af-con-01-error-catalogue.json),
copied from the design error catalogue. Within `v1`, changes are additive only, and
[`eng/compatibility/flagship-window.json`](../eng/compatibility/flagship-window.json)
holds the baselines the wire-compatibility gate compares every later change with.
Pin every Contracts package of one candidate to the same exact version.

## Offline inventory tool (`ArcForges.Cli`)

`ArcForges.Cli` is a .NET tool that validates the shape and declared bounds of an
`inventory.v1` document offline; it does not verify archive bytes, hashes, signatures or
trust. It declares the command `arcforges-contracts`. Install an exact version into a
tool path or a tool manifest:

```text
dotnet tool install --tool-path .tools ArcForges.Cli --version 1.0.0-ci.12.1
.tools/arcforges-contracts validate-inventory inventory.json
```

Exit code 0 means the document is valid, 1 that it is invalid or unreadable, and 2 a
usage error.

**Release note: command renamed (AF-CON-02).** Versions published after AF-CON-02 declare
`arcforges-contracts`. Earlier published versions declared `arcforges`, the command of
the ArcForges product CLI, so both on one PATH collided (ArcForges-Design conflict
C-03). Earlier versions are immutable: they keep the `arcforges` command and stay
resolvable, and none is unpublished, deprecated or deleted. A script that pins an earlier
version keeps working; a script that moves to a newer version calls `arcforges-contracts`.
The `validate-inventory` arguments, results and exit codes are unchanged. Flagship
installers never install this tool.

## Internal npm package

`@arcforges/ai-internal` is the one retained npm package. It carries the internal
AI/Cloud HTTP schema records and validators for the Cloudflare thin adapters. It is
published to the public npm registry (`publishConfig` access `public`), but its
contract access is `internal`: public clients must not import it, and registry
visibility does not change that boundary. Install an exact version and commit the
lock:

```text
npm install --save-exact @arcforges/ai-internal@1.0.0-ci.12.1
```

Before the first stable release, CI advances its `latest` tag to the newest
published main build; afterwards, stable releases own `latest` and main builds use
`ci`. Moving a tag does not rewrite an existing application's dependency version or
lock file.

## Retired TypeScript and Kotlin packages

No new version of npm `@arcforges/proto`, `@arcforges/api-client`,
`@arcforges/contract-fixtures` or `@arcforges/operator-client`, or of Maven
`io.github.arcforges:contracts-proto`, `contracts-connect-client` or
`contract-fixtures`, is published (CON.40). Already published versions stay
immutable and resolvable: nothing is unpublished, deprecated or deleted, so an
existing exact pin and its lock keep restoring. They receive no further schema,
fixture or security update; a consumer that needs one moves to the C# packages.
The native-grpc-only Maven `contracts-client` was retired at WP03.00 in the same
way. The former TypeScript and Kotlin installation examples are history; see
[the retired Maven guide](maven-central.md) and the retired Kotlin plans linked from
the README.

## Updating a dependency

Select an accepted new version, update the explicit manifest/central version and
lock, then run the consuming application's tests before merging. Dependabot can
open these update PRs in each consuming repository; the producer cannot configure
an unrelated repository's update policy. Do not use floating `*` versions or a
moving dist-tag as a committed production dependency.

No consumer needs protoc, Git submodules, a checkout of Contracts or access to
DesktopPlatform. NuGet (and npm, for `@arcforges/ai-internal`) download the published
dependencies normally.
