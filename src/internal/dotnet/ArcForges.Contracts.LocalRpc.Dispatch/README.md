# ArcForges.Contracts.LocalRpc.Dispatch

Internal boundary dispatch adapters for the local product operations (CON.43, DP-01 to DP-06). This is the
only Contracts assembly where the structured value (`CapabilityArguments`, `CapabilityResult` and
`StructuredValue`) meets the typed Scope and Chat requests. It contains no listener, gRPC service,
registration or product implementation.

Apache-2.0. Every C# file is generated by `eng/local_operations.py` (run through
`python eng/contracts.py generate`) from the pinned closure descriptor set, the merged constraint snapshots,
the operation-metadata rows of `eng/operations` and the operation-scope gate. Never edit
`Generated/Operations` by hand; `generate --check` refuses drift, missing files and stale files.

## Generated surface

- `LocalOperation` and `LocalOperationCatalog`: the closed set of tool-eligible operations, every section 6
  `IScopeOperations` and `IChatOperations` method of registry 04 except the AZ-04 human-only decision
  `IChatOperations.SubmitApproval`. Infrastructure-port methods are not model-callable and get nothing.
- `LocalToolAllowlist`: the closed allowlist (DP-04), a compile-time switch over exact capability keys. It
  holds an entry only for an operation that the operation-scope gate admits as a tool row
  (`authorization.capability` equal to its exact operation ID and the agent actor reachable). An eligible
  name or a generated port alone admits nothing. At CON.43 it holds exactly
  `IScopeOperations.CreateAnnotation` (the S61(2) admission); the manifest `toolAllowlist` is not a second
  admission source.
- One static class per operation (for example `ScopeCreateAnnotationOperation`) with the operation ID, the
  request and result schema IDs (the typed message names), the canonical request and result schemas in the
  `arcforges.local-operation-schema.v1` dialect, and four functions:
  - `TryDecode(arguments, meta, context, out request, out fault)` checks the envelope and schema ID, the
    local call context (present, valid and carrying an actor), the caller's request meta, decodes every
    field with its bounds, binds a copy of the meta and runs the owner shape validation. The typed request
    is returned only when everything passes; no owner code runs on a fault and nothing is partially applied.
  - `TryEncodeResult(value, out result, out fault)` validates the owner result, encodes it and validates the
    structured result before delivery.
  - `TryDecodeResult` and `TryEncodeArguments` are the symmetric legs.
- `LocalOperationFault` with `LocalOperationFaultKind` and a JSON-pointer path. `ToArcError` maps every fault
  to `validation.invalid_request` (category validation, no retry, did not happen).

Consumers wrap these functions in their own thin adapters and pin the exact package version (see
`docs/consuming.md`). The ArcForges.Capabilities decoder and encoder delegates return
`ArcForges.Foundation.Errors.Outcome`, a DesktopPlatform type that Contracts does not reference, so they
cannot bind to the emitted functions by method group. APP.03 wraps them for `arcscope.annotation.create`.

## Admission source

The allowlist has one admission source: the operation-metadata rows of `eng/operations`, as passed by
`eng/check_operation_scope.py`. The generator runs that gate and refuses to generate when it fails. It emits
an allowlist entry only for an eligible row whose `authorization.capability` is its exact operation ID and
whose actors, by the gate's own rule, reach the agent. The `toolAllowlist` of
`eng/operation-scope-manifest.json` is not a second source: a key listed there without such a row admits
nothing, and the list stays empty.

At CON.43 the one admitted row is `IScopeOperations.CreateAnnotation` (S61(2): profile `product-handler`,
actor kinds human, product-handler and agent, risk R2, per-operation approval). The gate admits it through
one exception keyed to exactly that row. An eligible operation without a declared profile row also refuses
generation.

## Fault kinds

| Kind                | Meaning                                                                      |
| ------------------- | ---------------------------------------------------------------------------- |
| `UnknownCapability` | the capability key is not in the allowlist (raised by the consumer adapter)  |
| `SchemaMismatch`    | the arguments or result carry another schema ID                              |
| `InvalidEnvelope`   | no value, or the envelope fails the platform shape validation                |
| `MissingMeta`       | no request meta was supplied with the arguments                              |
| `MissingContext`    | the local call context is missing or invalid                                 |
| `MissingActor`      | the local call context carries no actor                                      |
| `WrongKind`         | a value has a different StructuredValue kind than the schema declares        |
| `ExplicitNull`      | an explicit null where the field allows none                                 |
| `MissingRequired`   | a required field, or the member of a required oneof, is absent               |
| `UnknownField`      | a record key that the message does not declare (including `meta`)            |
| `OutOfRange`        | a value outside its type range or declared bounds (length, pattern, minimum) |
| `TooManyItems`      | a list or record above its declared maximum or 200 items                     |
| `TooDeep`           | nesting deeper than 16 levels                                                |
| `OneofConflict`     | more than one member of a oneof                                              |
| `InvalidIdentity`   | a foundation `Id` that is not canonical nonzero lowercase UUID text          |
| `InvalidBytes`      | bytes that are not canonical unpadded base64url text                         |
| `InvalidEnum`       | an enum name that is unknown or the UNSPECIFIED value                        |
| `ShapeInvalid`      | the owner shape validation refuses the typed request or result               |
| `Unrepresentable`   | a typed value the structured value cannot carry (a uint64 above 2^63 - 1)    |

The path is a JSON pointer (RFC 6901) into the structured value; it is empty for the whole value.

## Value mapping

| Protobuf field                      | StructuredValue                                                     |
| ----------------------------------- | ------------------------------------------------------------------- |
| message                             | record keyed by the authored JSON names; unknown keys refused       |
| request `meta`                      | never an argument; a `meta` key is an unknown field                 |
| repeated                            | list (at most 200 items, or the declared maximum)                   |
| string                              | text                                                                |
| bool                                | boolean                                                             |
| double, float                       | number (finite)                                                     |
| int32, int64, sint64, uint32        | integer within the type range and the declared bounds               |
| uint64                              | integer in [0, 9223372036854775807]; larger results unrepresentable |
| enum                                | text holding the proto value name; UNSPECIFIED refused              |
| bytes                               | canonical unpadded base64url text                                   |
| `arcforges.foundation.v1.Id`        | canonical lowercase UUID text, network byte order, nonzero          |
| `Instant`, `Decimal`, `ResourceRef` | the instant, decimal and resource kinds (DP-10 identity)            |
| nested `StructuredValue`            | itself                                                              |
| oneof                               | at most one member key; exactly one where the oneof is required     |

A record's keys are strictly ascending in ordinal order, explicit null is refused for every field except a
nested `StructuredValue`, nesting is at most 16 levels and a list or record holds at most 200 items. Missing
required fields, unknown fields and out-of-bounds values are typed faults. Cross-field owner rules are
enforced by the generated owner shape validation and reported as `ShapeInvalid`.

The encoders write record keys in ordinal order and omit unset fields and empty lists, so the encoded form is
canonical and decodes back to an equal typed message.
